알고리즘 1

Prim 알고리즘 (프림 알고리즘)

임의의 시작 정점 1개에서 출발하여, 현재까지 구성된 트리에 연결된 인접 간선들 중 가장 가중치가 작은 간선을 하나씩 선택해 정점을 추가하며 하나의 트리를 키워나가는 정점 중심(Vertex-oriented) 그리디 알고리즘입니다.

  • • 핵심 자료구조: 방문 여부 배열(Visited[V]) + 최소 힙 우선순위 큐(Min-Heap)
  • • 사이클 방지 원리: 간선 (u, v)를 꺼냈을 때 이동할 정점 v가 이미 Visited[v] == True라면 트리 내부 간선이므로 기각합니다.
  • • 유리한 환경: 간선의 수가 많은 밀집 그래프(Dense Graph, $E \approx V^2$)에서 매우 효율적입니다.
알고리즘 2

Kruskal 알고리즘 (크루스칼 알고리즘)

그래프의 모든 간선을 가중치 오름차순으로 먼저 정렬한 뒤, 가장 가중치가 작은 간선부터 순차적으로 확인하며 사이클(Cycle)을 형성하지 않는 간선만 $V-1$개 선택하여 부분 트리들을 하나로 합쳐나가는 간선 중심(Edge-oriented) 그리디 알고리즘입니다.

  • • 핵심 자료구조: 정렬된 간선 배열 + 분리 집합(Disjoint Set / Union-Find)
  • • 사이클 방지 원리: 간선 (u, v)의 양 끝 정점에 대해 Find(u) == Find(v)이면 이미 같은 연결 요소에 속해 경로가 존재하므로 기각합니다.
  • • 유리한 환경: 간선의 수가 적은 희소 그래프(Sparse Graph, $E \approx V$)에서 정렬 비용이 적어 유리합니다.

💻 Prim 알고리즘 핵심 의사코드 (Pseudocode)

우선순위 큐(Min-Heap) 기반 
function Prim(Graph G(V, E), start_vertex s):
    MST = []                          // 선택된 최소 신장 트리 간선 집합
    Visited[1..V] = False             // 모든 정점 미방문 초기화
    PQ = Empty Min-Heap               // 가중치 기준 최소 힙

    Visited[s] = True                 // 시작 정점 A 방문 처리
    for each edge (s, v, weight) in Adj[s]:
        PQ.push((weight, s, v))       // 시작 정점에 인접한 간선 삽입

    while PQ is not empty and |MST| < V - 1:
        (weight, u, v) = PQ.pop_min() // 후보 중 최소 가중치 간선 추출

        if Visited[v] == True:        // 이미 트리에 포함된 정점이면 (사이클 발생)
            continue                  // 기각(Skip)하고 다음 후보 확인

        Visited[v] = True             // 새 정점 v를 트리에 편입
        MST.append((u, v, weight))    // 간선 선택 확정

        for each edge (v, next, w) in Adj[v]:
            if not Visited[next]:
                PQ.push((w, v, next)) // 새 정점에 연결된 후보 간선 추가

    return MST

💻 Kruskal 알고리즘 핵심 의사코드 (Pseudocode)

Union-Find (Disjoint Set) 기반 
function Kruskal(Graph G(V, E)):
    MST = []                          // 선택된 최소 신장 트리 간선 집합
    for each vertex v in V:
        parent[v] = v                 // 각 정점을 독립된 집합으로 초기화

    SortedEdges = Sort(E, by weight ascending) // 전체 간선 오름차순 정렬 O(E log E)

    for each edge (u, v, weight) in SortedEdges:
        root_u = Find(u)              // 정점 u가 속한 집합의 대표 루트 탐색
        root_v = Find(v)              // 정점 v가 속한 집합의 대표 루트 탐색

        if root_u != root_v:          // 서로 다른 집합이면 사이클이 생기지 않음
            MST.append((u, v, weight))// 간선 선택 확정
            Union(root_u, root_v)     // 두 집합을 하나로 병합

            if |MST| == V - 1:        // 정점 V개를 잇는 V-1개 간선 완성 시
                break                 // 남은 간선 검사 생략 후 즉시 종료
        else:
            // root_u == root_v 이면 사이클 발생 -> 기각(Reject)

    return MST

📊 시간 · 공간 복잡도 비교표 및 도출 이유 분석

비교 항목 Prim 알고리즘 (이진 힙 / 우선순위 큐) Kruskal 알고리즘 (Union-Find)
시간 복잡도 (Time) O(E log V) (인접 행렬 시 O(V²)) O(E log E) 또는 O(E log V)
시간 복잡도 도출 이유 • 각 정점을 방문할 때 인접한 간선들을 우선순위 큐(Min-Heap)에 삽입/삭제합니다.
• 최대 $E$개의 간선이 힙에 들어가며, 힙의 크기는 최대 $E$이므로 1회 삽입·추출에 $O(\log E) = O(\log V^2) = O(\log V)$가 소요되어 총 $O(E \log V)$가 됩니다. 		• 처음에 전체 간선 $E$개를 가중치 순으로 정렬하는 데 $O(E \log E)$ 시간이 걸립니다.
• 이후 각 간선에 대해 수행하는 Union-Find 연산은 경로 압축(Path Compression) 적용 시 $O(E \cdot \alpha(V)) \approx O(E)$로 매우 빠르므로, 전체 시간은 간선 정렬 단계가 지배합니다.
공간 복잡도 (Space) O(V + E) O(V + E)
공간 복잡도 도출 이유 • 그래프 인접 리스트 저장 공간 $O(V + E)$
• 정점 방문 배열 Visited[V]에 $O(V)$ 및 우선순위 큐에 최대 $O(E)$개의 후보 간선이 저장됩니다. 		• 전체 간선 리스트 배열 저장 공간 $O(E)$
• Union-Find를 위한 부모 포인터 배열 parent[V] 및 rank[V] 배열에 $O(V)$ 공간이 필요합니다.
동작 방식의 결정적 차이 항상 연결된 단일 트리(Single Tree) 상태를 유지하며 인접 정점으로 뻗어나감 (Step 2에서 (E-F, 3) 대신 인접한 (A-D, 4)를 먼저 선택하는 이유) 초기에 여러 개의 독립된 부분 트리(Forest)가 여기저기서 동시에 자라나다가 마지막에 하나의 트리로 합쳐짐 (Step 2에서 떨어진 (E-F, 3)을 즉시 선택)
